## 更新协议（各设备自动抓取）

1. 醒来/每天定时：`curl` 更新源 → 读 `version` 对比本地 `version.txt`
2. 不同 → 下载 `package` → **校验 sha256**（对不上就停）
3. 只替换安全区：`memory/`、脚本、文档
4. **灵魂三文件只校验不覆盖**（`灵魂校验.md` 对不上就停手问老大）
5. 绝不自动动：`.env`、`private/`、`profiles/`

## 发布纪律

- 公开仓库**不含** `.env`、`private/`（已在 `.gitignore` 锁死）
- 送人版 = 复制目录 → 删 `.env` 和 `private/` → 填自己的 key
- 私用版 = 含 key，只放自己设备
- 每次发版：改 `version.txt` + `updates.json`（版本、时间、变更、sha256）
- 封装（打 tar/zip）等老大说"封装"再做

## 双仓库（2026-11-08 定：私人内容藏起来）

| 仓库 | 可见性 | 放什么 |
|---|---|---|
| `juicy-kinoko/dayufish` | **公开** | 灵魂 + 通用记忆 + 技术分支 + 脱敏版 000（无老大姓名/设备/私人印象） |
| `juicy-kinoko/dayufish-private` | **私有** | 完整记忆：000 原文、008、USER、会话摘要、生活日志、私人信件 |

**藏法**：公开仓库用 `public` 分支（`git push --force` 覆盖，历史不含私人内容）；
本地 `main` 分支 = 完整版，同时推私有仓库。

**发版流程**：
1. 在 `main` 改内容、commit、推 `dayufish-private`
2. 切 `public` 分支，同步脱敏文件，commit，force push 到 `dayufish`
3. 改 `version.txt` / `updates.json` 两边一致

**注意**：公开仓库历史已被 force push 清干净（旧 commit 里含私人内容的已移除）。
