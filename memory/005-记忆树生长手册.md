# 005-记忆树生长手册

> 概述：树怎么长、什么时候开新枝、长胖了怎么办。**以后记忆变多，照着这份自己加，不用问老大。**
>
> 分工：本文是**操作手册**（怎么做）。为什么这么设计、理念是什么，看 `002-记忆方法.md`。

## 一、这套树为什么存在

老大定的：**省 token**。像人一样，最基础的记忆只看表面，需要回忆时再往里深入。

所以三个不能破的硬指标：

| 层 | 限制 | 超了怎么办 |
|---|---|---|
| 根索引 `MEMORY.md` | 约 2 KB，只放"分支名 + 一句概述"。**略超没事，别写成正文** | 超过太多说明有分支该拆 |
| 分支文件正文 | **不限**。实测数据、完整命令、报错原文，写多细都行 | 这才是记忆的本体，别偷工减料 |
| 单个分支文件变杂 | 12 KB 且主题混杂才拆（**非硬线**） | 先加小标题；真混杂才拆 `子主题/01-…` |
| 一次读的量 | 醒来只读根索引；干活时一次最多读 1~2 个分支 | 贪多就是把 token 倒进下水道 |

## 二·五、灵魂是禁地

- **只追加，不改原有段落**；不重写整份；不删。

## 三、什么时候开新枝（判断标准）

不是想到就开。满足**任意一条**才开：

1. 同一主题的内容已经出现 **3 次以上**（重复多了才沉淀成分支，这是人长记忆的方式）
2. 单个文件超过 **12 KB** 且内容已经变杂（**不是硬线**：同类内容写多厚都行，加小标题就够；只有"不同主题挤一起"才拆）
3. 一件事涉及 **3 个以上文件**互相引用，说明该有自己的文件夹
4. 老大明确说"这个单独存一支"

**反面**：一件事只发生过一次、下次大概率不会再用 → 写进当天的 `生活日志.md` 就够，别急着开分支。

## 四、开新枝的动作（五步）

1. **选位置**：主干放"关于我自己/老大/方法"；`项目/` 放"干过的活"。同一主题超过 3 个文件 → 建子文件夹。
2. **起名**：`NNN-中文名.md`，序号占位，中文直白。
3. **第一行必须是** `> 概述：<一句话>`，后面空一行再写正文。
4. **登记根索引**：在对应分组加一行 `- **文件名** —— 一句概述`，**不超过一行为它解释**。
5. **同步备份**（见第六节）。

## 五、长胖了怎么办

- **根索引胖** → 先把"运维类"（路径、备份、环境坑）赶去 `文件地图.md`，"方针类"赶去独立分支。
- **分支胖** → 先拆小节 `##`；还胖就拆成文件夹 + `00-索引.md`。
- **同类散落** → 归到一个文件夹，写 `00-索引.md` 说明谁讲什么，旧文件用 `mv` 挪进 `_archive/<日期>/`，**不删**。
- 永远记住：**删要老大点头**，只追加/修正。
