# 008-凭据纪律

> 概述：两天里我泄漏了三次密钥，全是同一个错——想「脱敏打印」却漏了打码。这文件是我给自己钉死的规矩，不再靠临场小心。

## 硬规矩

1. **默认不主动往聊天里倒明文**。老大要 key，我先给三样：存放路径、名称清单、或者写进 `private/`（已 gitignore）给他本机看。理由：聊天会进本地日志、进会话摘要、进我的上下文，会被我带到任何地方。
   - 但**这是他的数据、他的机器**。他听完提醒还明确要，我就念，不磨叽——2026-11-10 15:12 老大第二次要求三个 git token，我念了，他说「没事，别担心」。
   - 念之前用一句话交代后果（哪些从此算"聊天里出现过"、去哪吊销），说完就念，不劝第二遍。
2. **不许用正则给整份凭据文件打码再打印**。今天就是这么漏的：只 mask 了 `secret|token|password` 三个字段名，`refs:` 段整段裸奔，9 把 key 直接进聊天。
   - 正确做法：**只打印我自己构造的字段**——名称、长度、前 4 字符。值从头到尾不进 stdout。
3. **接口回显也算泄漏**。测 OpenRouter `/api/v1/key` 时它返回 `label: sk-or-v1-401…3b6`，key 的头尾又被我贴出来一次。测 key 只取 `status` 码和身份字段，响应正文别原样打。
4. **测活不烧钱**：只调鉴权/模型列表接口，不调计费接口，不跑 completion。
5. **一旦泄漏**：立刻按钱包风险排序列「待轮换」，主动报，不等老大问。有钱包的第一位（DeepSeek ¥48.47）、有上限的第二位（OpenRouter $1000 档）、暂时 ¥0 的第三位。
6. **发布自检要覆盖所有 key 形态**，不只 `ghp_`。`sk-*`、`ms-*`、智谱的 `hex32.hex16`、`*_API_KEY:` 后跟长串，都得拦。自检命中只列文件名，不打印内容。

## 位置地图（别处不用找了）

- 引擎真正读的：`~/.dsh/.credentials.yaml` 的 `refs:` 段（10 条）
- 仓库 token：`private/credentials.yaml`（GitHub / Gitee / GitCode）
- `.env` 有 6 条**同名不同值**的旧 key（GLM4 长 22、ModelScope 24、OpenRouter 27，DeepSeek 空）——改 key 时两边都要改，或以主库为准清掉 `.env`
- 免费池 `.env.free` 里的 qnaigc 是有意公开的，不进轮换名单
