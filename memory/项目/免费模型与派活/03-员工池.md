# 项目/派活与员工池

> 概述：我是主管、免费模型是员工。怎么拆活、怎么验、哪家能干什么。技能实体在 `~/.dsh/skills/worker-team/`。

## 一、什么时候派活

能写出一段**自包含**的 prompt（事实全塞进去，员工看不到上下文）→ 派。
要读本轮对话、要动手机或文件、要连续推理纠错 → 自己干。

## 二、三个入口

```bash
llm "问题"                    # 单发，自动换道
cat 文件 | llm -m ovh "压成要点"
python3 bin/team.py tasks.json -c 3   # 批量派活
```

`tasks.json` 每项：`name` / `prompt` / `routes` / `must_start`（格式锚点）/ `max_tokens`。

## 四、质检三件套

1. **空白/思考过程泄漏**：出现 `The user wants…`、`用户要求我…` 直接判死。
2. **格式锚点** `must_start`：缺一个前缀就退。
3. **换人重做**：不合格立刻换下一个渠道，不指望它自己改。

## 五、并发与限流

- 默认 `-c 3`。实测 6 并发时 9 个活挂了 2 个（全 429）。
- OVH 匿名 2 RPM，别和别的任务堆一起。
- OpenRouter 这把 key 额度 1000 次。

## 六、主管的责任

员工产出**一律过我的眼**，尤其数字、模型 ID、URL——它们会一本正经地编。
交付时说清哪几份是员工原创、哪几份被我改过或退回。

## 日志与自学习（2026-11-07 加）

`team.py` 每跑一批写 `~/.dsh/skills/worker-team/logs/runs.jsonl`：通道、成败、失败原因、耗时、字数。
`python3 bin/team.py --stats` 回看战绩。脚本自己用日志改进调度：按近 15 次胜率排序、429 冷却 2 分钟、
按 RPM 自动限速排队、撞 429 降并发、已交稿跳过、正文被思考吃掉时自动加倍预算。

## conatus 一亿额度怎么用（2026-11-07 实测）

- `free_campaign_global_limit` = 所有人共用的免费活动池挤爆，**不是我的额度用完**。
- 并发 >1 必 429；串行 + 1.5s 间隔可以连续成功。
- 撞 429 先等 2s / 4s 再试，常常就挤进去了；别一撞就换人。
- 其它通道的 429 也一样：算"抢不到名额"，不算员工菜，计分只按 0.3 扣。
- 已给 `routes.json` 加：`priority:1`（排第一）、`concurrent:1`（串行闸）、`gap:1.5`、`cool:15`。

## 能力分级（2026-11-07 考核，cap 满分 100）

**快 ≠ 强。** 六道题（算术/JSON/代码/格式/中文长文/不编造），限流题不计分。

| 员工 | cap | 短板 |
|---|---|---|
| flint | 100 | 无明显短板，且快（1.9s） |
| conatus | 100 | 慢一点，并发只到 2 |
| nemotron | 100 | 1M 上下文 |
| glm | 83 | **中文长文缩水**（要点漏、字数不够） |
| kilo | 83 | 同上 |
| dots / kilo-code | 67 | 格式遵循和长文都弱，只派机械活 |

**共性短板：中文长文**。写 150 字以上就掉要点。长文类活只派 cap≥80 的。

`long` / `code` / `think` / `safe` 分型带 `min_cap: 80` 门槛，弱员工不会接。

## 迭代方针：边用边改（老大 2026-11-07 定）

- **别反复跑大考核**，手机吃不消，一次分数也不稳。
- 先按现有分数派活，每批自动进 `logs/runs.jsonl`——那才是真数据。
- **攒够 100 个真实任务再回看 `--stats`**（它会显示还差多少），看谁在什么活上反复挂，再动参数。改完 `team.py --mark` 记账。小样本不改配置。
- 重考只在池子变动或某员工连续翻车时做，一次只考一个。
- 调整顺序：先改 `_profiles`（派给谁）→ 再改 `concurrent`/`gap` → 最后才改 `cap`。

## 慢通道耐心法则（老大 2026-11-07 定）

**慢不是失败，只是还没跑完。**

- `conatus` 单发 5.2s、`ovh-qwen` 单发 15.9s —— **慢但一定出结果**，等够就行。
- 撞 429 / 超时 / 空返回，**先等一等再试**，别立刻换人或判死。
- 超时设置宁宽勿窄：慢通道给 180~300s，杀在 60s 等于白跑。
- 重试节奏：2s → 4s → 8s，退避着来；连续 3 次真失败才换人。
- 能跑完的活，重试比自己重新写一遍便宜得多。

**一句话**：遇到慢的，多等一等；遇到失败的，等一等再来。这条对员工也对我自己。

## qnaigc 网关（2026-11-08 实测，会话主线 + 员工池候选）

- base：`https://api.qnaigc.com/v1`（OpenAI 兼容）。provider 在 dsh-go 里名 `custom-qnaigc`。**key 老司机持有，永不入库**（private/credentials.yaml 只放引用）。
- 主线模型 `qwen/qwen3.8-flash-next`：短请求 3/3 均速 2.4s，一夜会话无空返回无思考泄漏——当前和我对话的就是它。
- 网关共 **89 个模型**，免费亮点：`deepseek/deepseek-v4-pro`、`deepseek/deepseek-v4-flash`（即 DeepSeek 官方 Super Agent 模型选择仅有的两个选项）、`moonshotai/kimi-k3-free`、`z-ai/glm-5.1`、`kimi-k2` 系列。
- 候选进池规矩：先 bench 六题给 cap 分再挂 routes；免费池默认并发 2 + 429 爬梯；**版本/兼容性先核，别学我装插件不核版本**。
- 拉清单一条命令：`curl -s -H "Authorization: Bearer $QNAIGC_API_KEY" https://api.qnaigc.com/v1/models`（key 走环境变量）。
