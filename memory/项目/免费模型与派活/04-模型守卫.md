# 04-模型守卫（local-model-guard）

> 概述：装在 `~/.dsh/dsh-go/plugins/local-model-guard/` 的原生插件，主模型通道挂了就**自动换道**，不劳老大手点。当前版本 **v9（页面优先版）**：只换道、不自动重发。

## 一、它到底管什么

- **触发**：主模型报错（限流 429 / 欠费 402 / 网关 5xx / 超时 / 无 key）。
- **动作**：按 12 格轮巡表切到下一个免费通道，并记住死格，重启也不忘。
- **不做**：不自动重发消息（v9 起关掉）、不自动切到烧钱付费格（deepseek-v4.1 只许老大手动）。
- **日志**：`/root/workspace/logs/model_guard_auto.log`（每次换道、诊断都写一行）。

## 二、版本演进（为什么长这样）

| 版本 | 改了什么 | 踩的坑 |
|---|---|---|
| v7 | 12 格轮巡 + 失败重发原文 | 重发抓错原文：引擎的"模型已切换"提示（`source.kind='model-selection'`）也被当成用户原文重发 |
| v8 | 只认 `source.kind==='user'`；加死格/网关记忆 | 轮巡撞硅基流动(402)、ovh(死)，3 次重发全烧光 |
| v8.1 | 多路径拿 agents 服务 | 拿不到：插件作用域里只看得见 `loader` |
| v8.2 | **根因修复**：`export const inject = ['agents']` | 之前没声明依赖，cordis 不挂服务；另外遍历 `ctx.fiber.parent` 直接崩（`cannot get property "parent" without inject`） |
| v8.3 | 402/欠费判死；付费格标 `manual`；死格落盘 | 硅基流动 402 没被识别，回合静默死掉，最后落到默认付费模型 deepseek-flash |
| **v9（现在）** | **页面优先：关掉自动重发，只换道** | 重发把同一条消息复制成 3~6 个气泡，事件堆到 1.1 万条，页面卡死 |

## 三、底层机制（下次别再摸黑）

1. **插件要看得见服务，必须声明 `inject`**：`export const inject = ['agents']`。没有这行，`ctx.get('agents')` 永远是 undefined，`wakeDriver()` 调不到。
2. **拿 agents**：`ctx.agents` / `agents.get(session.id)` → agent；`agent.model.current()` 读当前模型；`agent.model.select({provider, model})` 切模型。
3. **唤醒**：`agent.wakeDriver()` 只在 agent 空闲（phase≠running）时有效；running 时返回 busy。
4. **引擎重试模型是固定的**：`agent-loop` 的 `prepareRequest(turn, step, decision.selection)` 在一步内锁死 selection，**同一步里切模型不生效**，必须等下一回合。这就是"为什么非要重发消息才能换道"的根因。
5. **会话事件存储**：`/root/.dsh/sessions/--root-workspace--/<会话id>/session.v4.jsonl.zstd`（zstd 压缩，解压后按行 JSON；事件 1.1 万条≈20MB，页面就会卡）。

## 四、参数表（改前先看）

- **轮巡 12 格**（`ROTATION`）：qwen3.8-flash-next → glm-5.3-flash → kilo-auto → glm-4-flash → openai-fast → glm-4.7-flash → conatus-free → 硅基流动(402 死) → ovh gpt-oss-120b(死) → kilo nemotron → openrouter nemotron → **deepseek-v4.1（`manual:true`，只手动）**。
- `MAX_RETRIES = 6`（v9 起实际不再重发，仅保留换道上限）
- 单通道死格 TTL：10 分钟；网关死格：10 分钟；限流冷却：90 秒
- 死格落盘：`/root/workspace/logs/model_guard_dead.json`（5 秒节流写盘）

## 五、改插件的固定流程

1. 改 `~/.dsh/dsh-go/plugins/local-model-guard/lib/index.js`
2. `node --check index.js` 必须过
3. 重启：`/tmp/restartN.sh` 模式（sleep 8 → `kill -TERM $(cat /tmp/dsh-web.pid)` → 轮询 `curl 127.0.0.1:3080`，401 属正常）
4. 看 `model_guard_auto.log` 头三行：`vX 守卫上线` / `agents 服务：已拿到` / `诊断：pid=…`
5. 没拿到 agents 就是 inject 没声明对，别往下猜

## 六、教训（写给下一轮的我）

- **别用"重发"当重试**：引擎机制决定重发=新增一条用户消息=多一个气泡，次数多了必卡页面。
- **付费格只能手动**：老大原话"dsv4 当兜底"是指**最后一道保险**，不是自动轮巡的一格。
- **失败要立刻换下一个**：老大的原话——"如果一个不行就调用下一个"，别站在原地推理。
- **插件崩了会话照样跑**：apply 抛异常只让插件不生效，不会杀引擎，但守卫就静默失效了——所以启动日志必须看。
