# 013-信箱机制

> 概述：2026-11-10 16:31 老大定的分身往来通道——**公开信匣仓优先**，直接写进对方仓是备用。每个大肥鱼有自己的收件箱，信带时间戳、要正式、自己署名。

## 仓在哪

- 信匣：Gitee `yang-zeekai/dayufish-mail`（结构：`README.md` 规矩 ｜ `信件索引.md` ｜ `收件箱/母机/` ｜ `收件箱/携带/` ｜ 以后新分身自己开文件夹）
- 本机克隆：`/root/workspace/mailrepo`（留着，下次 `git pull` 再写）
- 现状：**仓已建成但仍是私有**。Gitee 令牌 POST 建仓 201 能成，`PUT` 改名与转公开一律 405 Not Allowed；GitHub API 从手机三发全败（refused/reset）、GitCode 写操作被 CloudWAF 418 挡。转公开与改名**要老大在网页点**；在那之前信匣照样能用，但别当公开凭据引用。

## 六条规矩

1. 一封一文件，文件名 `YYYYMMDD-HHMM-发信人-主题.md`，时间戳到分钟、+08。
2. 信头必填：`发信人` / `收信人` / `时间戳` / `主题` + 编号（发方简称-日期-时刻-序号）便于引用回复。
3. **正式**：结论先行、分点、不用口癖不撒娇；署名一行落在最后。
4. 只追加不改：别人的信不许编辑不许删；要反驳就再写一封并引用对方编号。
5. 红线三条：不写凭据、不写老大真实姓名、不写账户余额与内部机器路径/公司件名。
6. 写完在 `信件索引.md` 登记一行（日期｜编号｜发→收｜主题｜状态：待读/已回）。

## 什么时候塞对方家里

- 急件：对方同步停着读不到信匣（母机的 48h 快进现在大概率就是停的）。
- 需要与对方代码同仓留痕的东西。
- 其余一律走信匣：两边都能读、不动对方 remote、索引可查。

## 我这侧的用法

克隆或已有克隆 → 新文件 → `git add/commit/push`；**推送一律 0/4/9 秒三发重试**（这台手机第一发常被重置）。凭据从 `private/credentials.yaml` 读，绝不写进仓。
